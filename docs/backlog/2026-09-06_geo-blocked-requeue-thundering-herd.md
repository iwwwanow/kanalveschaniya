# requeueGeoBlockedIfProxyAvailable — весь backlog гео-блокированных треков разом в pending при старте

Подробности ресерча — `docs/diary/2026-09-06_oom-restart-storm-research.md`. При каждом старте
с настроенным `PROXY` (`infrastructure/adapters/yt-dlp.ts`,
`requeueGeoBlockedIfProxyAvailable()`) выполняется один `UPDATE queue SET status='pending' ...
WHERE block_reason='geo'` без лимита и без троттлинга — переводит в `pending` вообще все
гео-блокированные джобы разом. Дальше их разбирают как обычно `WORKER_CONCURRENCY` (по дефолту 3)
воркеров, но если накопился backlog и PROXY только что включили — сразу же на старте возникает
всплеск из нескольких параллельных повторных скачиваний ровно в момент, когда процесс и так
только что поднялся (holодный старт, ещё нет никакого "запаса" по памяти).

В сочетании с двойной буферизацией файла в память на аплоад (см.
`2026-08-26_upload-buffers-full-file-oom.md`) это правдоподобный усилитель шторма OOM-рестартов,
но не подтверждён по факту — не сопоставлялся с точным временем реального OOM (нужен прод-доступ
к `queue`/`error_log` с точными timestamp'ами). Идея на будущее, если подтвердится: троттлить
это восстановление (например, снимать гео-блок пачками с паузой, а не всё сразу одним `UPDATE`).
