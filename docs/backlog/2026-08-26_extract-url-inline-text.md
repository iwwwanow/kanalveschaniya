# `extractUrl` не находит URL внутри текста сообщения

Найдено в ревью 2026-08-24 (заметки на `infra/presentation/extract-url.ts`: "is it util?",
"can we parse all user message to url? it can include many urls on one message &
non-url text"). Реальный UX-пробел, не архитектурный. Сейчас `extractUrl(text)` матчит,
только если **всё** обрезанное сообщение целиком — валидный URL (`new URL(trimmed)`
должен успешно распарсить всю строку). Сообщение вида "вот трек https://youtu.be/xyz,
глянь" или сообщение с несколькими ссылками подряд не срабатывает вообще — бот отвечает
"Отправь ссылку на трек или плейлист", хотя ссылка там есть.

Используется в двух местах — `handle-message` (личка) и `channelPost`-хендлер
(`listen_channel`), оба в `infra/presentation/telegram-handlers.ts`.

**Фикс** — заменить точный `new URL()`-парсинг на извлечение URL по regex из произвольного
текста; при нескольких найденных ссылках — по аналогии с плейлистом заводить джобу на
каждую (fan-out), а не брать только первую молча. Не тривиально (меняет контракт
`extractUrl: string → string | null` на `string → string[]`, затрагивает оба вызывающих
хендлера), но и не архитектурная правка — можно делать независимо от остального
рефакторинга. Не блокирует мёрдж.
