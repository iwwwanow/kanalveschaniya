# `/healthz` не видит БД, а в docker `unhealthy` никто не рестартует

**Вывод.** 15.10 бот переехал с k3s на Alpine + docker compose (doco-cd). Флешку с базами (`/app/data`) выдернули на ходу, и бот остался `healthy`: `/healthz` (`src/infrastructure/presentation/health-server.ts`) проверяет только heartbeat event loop, а не доступность БД. Вторая половина — сама схема liveness: в k3s по проваленной пробе kubelet перезапускал контейнер, docker по статусу `unhealthy` не делает ничего, `restart: unless-stopped` срабатывает только на выход процесса. Так что и heartbeat сейчас ничего не лечит: зависший процесс (инцидент 2026-08-26/27) будет висеть `unhealthy` бесконечно. Комментарий в `src/main.ts` («A process that is actually wedged is caught by /healthz») при docker уже неверен.

**Идея.** Сделать так, чтобы бот сам выходил с ненулевым кодом, а не полагался на внешний перезапуск: watchdog внутри процесса (heartbeat протух → `process.exit(1)`; если сам event loop стоит, нужен отдельный `Worker`), и проверка БД (`SELECT 1` / запись в служебную таблицу) — при ошибке тоже выход. Тогда `restart: unless-stopped` закрывает всё без доработок инфраструктуры. Запасной вариант на стороне инфры — autoheal-контейнер, рестартующий `unhealthy`; но тогда `/healthz` всё равно должен проверять БД. Рядом — `2026-10-15_db-malformed-retries-instead-of-exit.md`: тот же принцип «выход процесса вместо работы в сломанном состоянии».
