# `NotifierPort.notify` / `TrackCachePort.deliver` — пересечение ответственности

Зафиксировано как открытый вопрос ещё в `docs/diary/2026-08-23_infra-restructure-plan.md`
(секция "Ревизия — 2026-08-24"), формализуется сюда, чтобы не потерялось. Оба метода
резолвят `jobId → chatId` через `telegram_reply_refs` и оба в итоге что-то отправляют
пользователю через Telegram Bot API:

- `NotifierPort.notify()` — свежескачанные байты через `sendMedia` (только когда
  `CACHE_TO_CHANNEL=false`, т.е. кэш выключен)
- `TrackCachePort.deliver()` — форвард уже существующего сообщения из канала через
  `forwardMessage` (на cache-hit, когда кэш включён)

Не полный дубль (разные API-вызовы, разные источники данных), но смысловое пересечение
("по jobId достать адрес и послать что-то в Telegram") есть — два порта, которые в
принципе могли бы быть одним с двумя реализациями метода "доставить результат". Решение
на сессии 2026-08-24 — **не трогать сейчас**, оставить как есть, порог сложности объединения
не оправдан текущим объёмом кода. Не блокирует. Пересматривать, если появится третий
похожий кейс "резолви jobId и пошли в Telegram" — тогда правило "трёх" оправдает абстракцию.
